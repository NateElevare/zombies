# DEAD ZONE: Architecture (v0.3, Phaser 4 + TypeScript rebuild)

DEAD ZONE is a top-down zombie survival RPG. It has two modes: **Survival**, the main game (a huge procedural city, looting, a base, tech trees, day/night and hordes), and **Arcade** (wave survival in a small arena).

This version rebuilds the vanilla-canvas prototype on Phaser 4 + TypeScript.
- The prototype lives in `legacy/` (open `legacy/index.html`) and is the reference for the game rules: `legacy/SURVIVAL_SPEC.md` and `legacy/js/sv/*.js`.
- The port keeps all the gameplay and fixes from the prototype, and upgrades rendering, art, lighting and structure.
- All art is generated by our own code in `art/`. We do not use downloaded or bought assets.

## Stack and commands
| | |
|---|---|
| Engine | `phaser@4.2.1` (WebGL). Types are in `node_modules/phaser/types/phaser.d.ts`; check APIs there, because Phaser 4 is not Phaser 3. |
| Language | TypeScript 7 in strict mode, ES modules, bundled by Vite 8 |

## Layers (strict)
```
src/sim/     pure game simulation; NO phaser, NO DOM (save.ts may touch localStorage, guarded)
src/render/  Phaser rendering of sim state: world, sprites, animation, lighting, fx, camera
src/ui/      DOM overlays (inventory, loot, tech, craft, map, pause, dead, title) and the HUD
src/audio/   WebAudio synthesized SFX, driven by sim events
src/scenes/  Phaser scenes: Boot (load assets), Title, Game (the shell: input -> fixed-step sim -> render -> drain events)
src/input.ts keyboard/mouse -> InputState (action based, so rebinding/gamepad/touch can be added later)
art/         procedural art generators -> public/assets
tests/       vitest
```
Rules:
- The sim never imports from render, ui or audio.
- Render, ui and audio read `GameState` and call the sim action functions below.
- Communication from sim to the outside goes only through `state.events` (see `SimEvent` in `src/sim/types.ts`).

## Simulation loop (fixed timestep)
- `SIM_DT = 1/60`. The Game scene accumulates real frame time, then runs `step(state, input, SIM_DT)` up to 5 times per frame and drops any excess. This removes the variable-dt jitter of the prototype and keeps the sim deterministic, which co-op and replays will need later.
- At the start of every tick, `step` copies `x,y,angle` into `prevX,prevY,prevAngle` for the player, zombies and bullets.
- The renderer draws at `lerp(prev, cur, alpha)`, where `alpha = accumulator / SIM_DT`, so motion is smooth at any refresh rate (60/120/144/165Hz).
- All sim randomness goes through the state RNG (`rand(state)` in core.ts). World generation uses `makeRng(seed)`. The sim never calls `Math.random`.
- Pausing: the sim runs a tick only when `state.screen === 'playing' && !state.paused && (state.ui === null || state.ui === 'build')`. The clock and timers do not advance otherwise.

Porting notes:
- Replace `Z.emit/Z.sv.toast/Z.audio.play/Z.particles.*/Z.sv.ui.open` with `emit(state, …)` events. Use `{t:'sound',…}` for audio, `{t:'blood'|'bulletHit'|'shot'…}` for FX, and `{t:'openUi',…}` to open UI.
- Replace `Z.input` with the `InputState` passed into `update`/`step`. `firePressed` and `pressed` are edge-triggered per tick.
- Remove all drawing code from the sim. The `draw*` functions are rewritten in src/render.
- Set the new fields (`vx, vy, variant, attackT, lastShotT, swingTotal, prev*`, `Solid.sub/vseed/orient`, `Building.floor/roof/wall`). The renderer depends on them.
- World gen: every solid and decor gets a `sub` (visual subtype) and a `vseed`. The meaningful sets are listed in ART_SPEC.md §Environment.

## Rendering (src/render) summary
- Ground uses chunked `DynamicTexture`s, built from tile textures and decals, with LRU eviction.
- Walls, props, structures and drops are image objects culled to the camera.
- Roofs fade out for the building the player is in.
- Characters are layered sprites: legs follow movement direction, the torso and held weapon follow the aim. Animation speed scales with velocity.
- Lighting: a darkness layer, a flashlight cone with wall shadows (a visibility polygon from blocksSight solids), an ambient circle around the player, campfire and muzzle-flash lights. Darkness is ~0.15 at day, ~0.97 at deep night and darker indoors.
- FX are particle emitters and decals driven by sim events.

## Art pipeline
See ART_SPEC.md. Generators write texture atlases (Phaser JSON-hash) plus `public/assets/manifest.json` and `public/assets/anims.json`. The renderer loads the manifest and creates every animation generically, so new art needs no renderer code.

## Testing
- `tests/*.test.ts` are unit tests per sim module.
- `tests/smoke.test.ts` is a scripted full-game run with InputState scripts: loot, menus, leveling, tech, building, crafting, night, horde, death, death bag, respawn, save/continue, and an arcade waves run.
- `npm run typecheck` must pass.
- Render and ui are verified by headless Edge screenshots (`tools/`) and a perf recorder.
